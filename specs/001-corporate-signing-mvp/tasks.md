# Tasks: 001 Corporate Signing MVP

**Input**: [plan.md](plan.md) (runtime, runner contract, mode registry, governed invariants), [spec.md](spec.md), [data-model.md](data-model.md), [contracts/](contracts/), [research.md](research.md), [quickstart.md](quickstart.md).

Status: planned. Every implementation task is intentionally unchecked. This file is the only executable build checklist; the OpenSpec tasks hold governance and handoff only.

**Conventions.**
- `files:` paths are relative to the paired code worktree.
- Every `verify:` runs from the code tree with `PATH="$PWD/tools/node/bin:$PATH"`, after `sh scripts/fetch-node.sh` and `npm ci`.
- Every mode used below is pre-registered by T001 in `scripts/verify-modes.mjs` (plan.md § Mode registry).
- Tier tags follow the shared rubric. 40 tasks are `[O]` (security-sensitive, cross-module, contract or governed paths) and 1 is `[S]`. No `[H]` task qualifies.

**Orchestrator checks for every task after T001.**
1. **Freeze.** `git diff --quiet <T001-sha> HEAD -- scripts/verify.mjs scripts/verify-modes.mjs tests/tooling/verification-runner.test.mjs`, where `<T001-sha>` is the current governed runner commit: amendment A-007 in plan.md, which supersedes the A-006 baseline. The runner, its registry and its self-test are frozen there, and no later task lists them.
2. **Scope.** The task's commit touches only its `files:`.
3. **Verify.** The task's `verify:` exits 0 and its final line reads `PASS`.
4. **Regression.** `npm run verify -- no-secrets` and every earlier task's mode still pass.

**How runner statuses are handled.**
- `CAPABILITY_ABSENT` (exit 3) is recorded as **environment-blocked**. It is never a pass, and it never climbs the model-escalation ladder.
- `VACUOUS`, `EVIDENCE_MISSING` and `ENV_MISMATCH` are failures.

**Writer brief hygiene** (risk report § C):
- Engineering language only.
- Synthetic fixtures are generated programmatically.
- Writers return summaries only: case IDs, counts and pass/fail tables, never key, token or fixture bytes.
- The T012 oracle writer gets a fresh context. Its brief excludes `src/cryptograph/` and `src/verifier/`, and T013/T036/T037/T014 writers never edit `tests/integrity/oracle/`.

## Dependencies and execution order

The default execution is strictly sequential in the order listed, with one writer per code worktree. No `[P]` marker appears. The only parallelism is the two Phase 2 writer lanes defined below (sequencing amendment A-005). Two dependency rules span the whole list: no package is added after T027, and the runner is frozen at the A-007 runner commit (earlier baselines: a71b3bc, then f31842b under A-006).

**Phase 1.** T001 → T026 → T001 hardening round (A-006) → T002 → T027 → T001 runner round (A-007) → T002 platform-inventory follow-up (A-007). Each runner round reuses T001's `files:` and verify command and moves the freeze baseline. The T002 follow-up reuses T002's.

**Phase 2: two disjoint writer lanes (amendment A-005).** Both lanes start only after Phase 1 (T001, T026, T002, T027) is accepted.

- **Lane A** (main code worktree `worktrees/001-corporate-signing-mvp/code`, feature branch `001-corporate-signing-mvp`): T003 → T028 → T029 → T030. That is storage, then the blob store, then the audit chain and retention, then outbox and restore.
- **Lane B** (second code worktree `worktrees/001-corporate-signing-mvp/code-lane-b`, temporary branch `001-corporate-signing-mvp-lane-b`, cut from the accepted Phase 1 head after T027): T004 → T033 → T005 → T031 → T032. That is fixtures and the dev launcher, then the parse service (which needs the T004 fixtures), then auth, then the server, then notifications.

**Lane rules.**
- **Disjoint by construction.** No `files:` path or directory prefix of a lane A task overlaps one of a lane B task. No Phase 2 dependency edge crosses lanes. Neither lane lists `package.json`, `package-lock.json` or a frozen runner file. A lane B task must not import `src/storage/` or `src/domain/canonical/`, and a lane A task must not import `src/server/`, `src/api/`, `src/pdf/`, `src/notifications/` or `fixtures/`. Any task found to overlap would run sequentially instead.
- **One writer per worktree, per-task checks unchanged.** Each lane has exactly one writer. Each worktree fetches its own runtime with `sh scripts/fetch-node.sh` into its own gitignored `tools/`. Every task keeps the full orchestrator checks: the freeze diff against the current runner freeze commit (A-007), scope, the task's verify, `no-secrets`, the transcript model check, and regression of every Phase 1 mode plus the earlier modes of the same lane.
- **Integration.** The orchestrator cherry-picks each accepted lane B commit onto the feature branch, in lane order, with no squash and per-task commits preserved. A conflict stops integration and is reported; it is never resolved by editing task files. Lane A commits land directly on the feature branch.
- **After both lanes are integrated:** every Phase 2 mode (`storage`, `blobs`, `audit-chain`, `outbox-restore`, `dev`, `parser-limits`, `auth`, `server`, `notifications`) is re-run on the integrated head. Then the phase-end regression reviewer and the validation runner run. Finally the lane B branch is deleted and the `code-lane-b` worktree removed.
- **Later phases.** US1 and every later phase stay strictly sequential in the main code worktree, unless a later amendment says otherwise.
